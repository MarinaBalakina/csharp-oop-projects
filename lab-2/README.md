# 📬 Corporate Message Distribution System

Проект на C#, моделирующий корпоративную систему доставки и обработки сообщений.

Сообщения могут отправляться пользователям, группам получателей или в архив. Для отдельных адресатов можно настраивать фильтрацию по важности, логирование и систему оповещений.

## 📌 Основная идея

Система строится вокруг универсального получателя сообщения. Благодаря общему интерфейсу сообщение можно передать пользователю, архиватору или сразу группе адресатов.

Дополнительное поведение — фильтрация, логирование и уведомления — подключается отдельно, не изменяя основную логику доставки.

## Основные сущности

### Message

Сообщение содержит:

- заголовок;
- основной текст;
- уровень важности;
- время создания.

Для важности используются уровни от `Low` до `Critical`.

### User

Пользователь является одной из конечных точек доставки.

При получении сообщения создаётся отдельная запись со статусом `Unread`. Пользователь может отметить её прочитанной, после чего статус меняется на `Read`.

Повторная попытка отметить уже прочитанную запись обрабатывается как ошибка.

### Recipient

Общий интерфейс для всех адресатов системы.

На его основе реализованы разные варианты получателей:

- пользователь;
- архиватор;
- группа адресатов.

### Recipients Group

Позволяет объединить несколько получателей и передать одно сообщение каждому из них.

Группа может содержать адресатов разных типов и дополнительные обёртки с фильтрацией или логированием.

### Topic

Топик объединяет получателей под одним названием.

При отправке сообщения через топик оно автоматически передаётся всем подключённым к нему адресатам.

### Importance Filter

Фильтр ограничивает доставку сообщений по уровню важности.

Если важность сообщения ниже установленного значения, оно не передаётся получателю.

### Logging

Для выбранного адресата можно добавить логирование процесса доставки.

Логгер вынесен в отдельную абстракцию, поэтому его поведение можно проверять независимо от конкретного способа записи логов.

### Notification System

Система может анализировать текст сообщения и реагировать на заданные ключевые слова.

Поддерживаются два варианта уведомлений:

- текстовое сообщение;
- звуковой сигнал.

### Archiving

Сообщения можно сохранять двумя способами:

- непосредственно в памяти приложения;
- в отформатированном виде через отдельный форматтер.

Форматированный архив использует Markdown-представление заголовка, важности и содержимого сообщения.

### Formatting

Форматирование разделено на отдельные компоненты для заголовка и тела сообщения.

Полученный результат может быть отправлен в разные хранилища, например в файл или консоль.

## Тестирование

В проекте проверяются следующие сценарии:

- новое сообщение пользователя получает статус `Unread`;
- непрочитанное сообщение можно отметить как `Read`;
- повторное изменение статуса прочитанного сообщения вызывает ошибку;
- сообщение ниже установленного уровня важности блокируется фильтром;
- при доставке сообщения вызывается логгер;
- форматирующий архиватор корректно вызывает хранилище и формирует Markdown;
- при использовании двух адресатов для одного пользователя фильтр предотвращает лишнюю доставку сообщения.

Для проверки зависимостей используются собственные mock-объекты, которые отслеживают вызовы получателей, логгера и хранилища.
