# 🗂️ File System Manager

Проект на C#, реализующий консольную систему для навигации и управления файловой системой.

Приложение позволяет подключаться к выбранной директории, перемещаться по дереву каталогов, просматривать файлы и выполнять основные операции над ними с помощью текстовых команд.

## 📌 Основная идея

Система работает как небольшой файловый менеджер с собственным командным интерфейсом.

Пользователь вводит команды с параметрами и флагами, после чего они разбираются парсером и преобразуются в отдельные объекты команд.

Логика работы с файловой системой отделена от консольного ввода и вывода, поэтому способ взаимодействия с программой и конкретную реализацию файловой системы можно заменять независимо.

## Основные возможности

### Connection

Перед началом работы приложение подключается к выбранной директории файловой системы.

После подключения эта директория становится корнем, за пределы которого пользователь выйти не может.

Систему также можно отключить и подключить к другому расположению.

### Navigation

Поддерживается навигация по каталогам с помощью:

- абсолютных путей;
- относительных путей;
- `.` для текущей директории;
- `..` для перехода на уровень выше.

### Directory Tree

Содержимое каталога можно вывести в виде дерева.

Глубина отображения задаётся параметром, а символы для файлов, директорий и отступов могут настраиваться отдельно.

### File Operations

Система поддерживает основные действия с файлами:

- просмотр содержимого;
- копирование;
- перемещение;
- удаление;
- переименование.

Для операций можно использовать как абсолютные, так и относительные пути.

### Command Parser

Пользователь взаимодействует с приложением через команды.

Парсер отвечает за распознавание команды, её аргументов и флагов и создаёт соответствующий объект команды для дальнейшего выполнения.

Примеры поддерживаемых команд:

- `connect`
- `disconnect`
- `tree goto`
- `tree list`
- `file show`
- `file move`
- `file copy`
- `file delete`
- `file rename`

### File System

Работа с файлами вынесена за отдельную абстракцию.

Благодаря этому основная логика приложения не зависит напрямую от локальной файловой системы и может быть расширена другими реализациями.

## Особенности архитектуры

Проект строится с разделением основных обязанностей:

- парсинг команд отделён от их выполнения;
- команды представлены отдельными объектами;
- работа с файловой системой скрыта за абстракцией;
- вывод данных не зависит напрямую от консоли;
- параметры команд можно расширять без изменения существующей логики парсера;
- структура каталогов загружается по мере необходимости, без хранения полного дерева файловой системы в памяти.

Такой подход позволяет соблюдать принципы SOLID и упрощает дальнейшее расширение системы.

## Тестирование

Основное внимание уделяется проверке командного парсера.

Тесты должны подтверждать, что:

- команда определяется корректно;
- позиционные аргументы передаются в нужные поля;
- именованные флаги обрабатываются правильно;
- создаётся объект ожидаемого типа;
- параметры команды сохраняют переданные значения.
