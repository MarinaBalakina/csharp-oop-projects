# 🏦 Banking Account Management System

Проект на C#, реализующий систему управления банковскими счетами через Web API.

Пользователь может создать сессию, получить доступ к своему счёту, проверить баланс, пополнить его, снять средства и посмотреть историю операций. Для административных действий используется отдельная admin-сессия.

## 📌 Основная идея

Работа с системой строится через сессии.

Для пользовательской сессии необходимо указать номер счёта и PIN-код. После успешной авторизации создаётся уникальный ключ сессии, который используется при дальнейших операциях.

Административная сессия создаётся отдельно с помощью системного пароля и позволяет выполнять действия, недоступные обычному пользователю.

Все операции со счётом проходят проверку данных и прав доступа, а успешные действия сохраняются в истории.

## Основные возможности

### Accounts

Система позволяет:

- создавать банковские счета;
- хранить номер счёта и PIN-код;
- получать текущий баланс;
- пополнять счёт;
- снимать средства;
- предотвращать снятие суммы, превышающей доступный баланс.

### Sessions

Реализовано два типа сессий:

- пользовательская;
- административная.

Каждая созданная сессия получает уникальный ключ.

Пользовательская сессия связана с конкретным счётом, поэтому операции выполняются только над тем аккаунтом, для которого была пройдена авторизация.

### Operation History

Действия со счётом сохраняются в истории операций.

Запись содержит информацию о выполненной операции, счёте, балансе после её выполнения и времени создания записи.

Историю может получить пользователь, имеющий действующую сессию для соответствующего счёта.

### Data Validation

Для важных значений используются отдельные типы вместо обычных строк и чисел:

- номер счёта;
- PIN-код;
- денежная сумма;
- сумма транзакции;
- ключ сессии.

Каждый такой объект проверяет корректность своего значения ещё до выполнения основной бизнес-логики.

### Error Handling

Ожидаемые ошибки системы обрабатываются через Result-объекты.

Например:

- неверный номер счёта;
- неправильный PIN-код;
- отсутствие нужных прав;
- некорректная сумма;
- недостаточный баланс.

На уровне Web API эти ошибки преобразуются в соответствующие HTTP-ответы.

### Web API

Для взаимодействия с системой реализован ASP.NET Core Web API.

Через контроллеры доступны операции:

- создания пользовательской сессии;
- создания административной сессии;
- создания счёта;
- получения баланса;
- пополнения;
- снятия средств;
- просмотра истории операций.

## Архитектура

Проект построен с использованием **гексагональной архитектуры**.

Основная бизнес-логика не зависит напрямую от Web API, хранения данных или других внешних компонентов. Вместо конкретных реализаций она работает через интерфейсы.

Например, сервис управления счетами не знает, что данные сейчас хранятся в памяти. Он работает только с абстракцией хранилища.

Это позволяет заменить in-memory хранение на базу данных без изменения основной логики приложения.

Связывание интерфейсов и их реализаций выполняется через `Microsoft.Extensions.DependencyInjection`.

Такая архитектура хорошо подходит для этого проекта, потому что банковская логика должна быть отделена от технических деталей. Это упрощает развитие системы, замену способов хранения данных, добавление новых интерфейсов взаимодействия и тестирование бизнес-логики отдельно от Web API и инфраструктуры.

## Особенности реализации

В проекте используются:

- отдельные сервисы для работы со счетами, сессиями и историей;
- Repository-подход для хранения данных;
- фабрики для создания счетов и сессий;
- Value Objects для проверки важных значений;
- Dependency Injection;
- отдельный источник времени через интерфейс;
- отдельный провайдер системного пароля;
- преобразование бизнес-ошибок в HTTP-коды;
- in-memory реализации хранилищ;
- Result Pattern для обработки ошибок без исключений в бизнес-сценариях.

## Тестирование

Тесты проверяют именно бизнес-логику работы со счётом и не зависят от Web API или реального способа хранения данных.

Проверяются следующие сценарии:

- при пополнении счёта баланс увеличивается на правильную сумму;
- после пополнения создаётся запись в истории операций;
- при успешном снятии средств баланс уменьшается;
- после снятия создаётся запись в истории;
- при попытке снять больше доступной суммы возвращается ошибка `InsufficientFunds`;
- при неуспешном снятии баланс остаётся без изменений;
- неуспешная операция не добавляется в историю.

Для тестирования используются собственные fake-реализации хранилищ, фабрики и источника времени. Благодаря этому тесты проверяют только работу `AccountService`, не затрагивая инфраструктуру.
